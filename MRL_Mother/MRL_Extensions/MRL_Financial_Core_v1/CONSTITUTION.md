## 目標與適用邊界

重新設計制度的出發點：數位操作成功，不自動代表轉移符合資產權利人的意願。
制度須同時保護支付可用性、持有人權利、證據完整性、被指控者的異議權及收款人的交易安全。
「重建」由 MRL 自有測試帳本起步；跨入銀行或既有公鏈需要相對應的合作介面。
本草案不宣稱 MRL 可單方面改變其他帳本、剝奪他人資產或裁定所有權。

## 制度分工

| 角色 | 職責 | 不能自行完成的動作 |
| --- | --- | --- |
| 原持有人／付款人 | 提出簽署指令、保留權利證據、提出爭議 | 單方認定失竊後直接扣款 |
| 收款人 | 接受支付、提交反證、提出異議 | 覆寫原始付款紀錄 |
| MRL Agent | 整理材料、產生請求、重播驗證及差異核對 | 持有裁決私鑰、代替 quorum 或預設竊賊身分 |
| 發行與帳務管理者 | 依核定規則發行、對帳及揭露 | 無準備資產卻宣稱可贖回真實貨幣 |
| 爭議審理者 | 審查證據、利益衝突與裁決理由 | 用單一簽章隱密改帳 |
| 獨立稽核者 | 比對外部 checkpoint、簽章及借貸平衡 | 把完整性驗證當成權利判決 |

原型以不同 Owner／委員會公鑰及多數驗簽表示權責分離；公鑰不同不能證明現實中由不同人控制。
發行委員會與審理委員會在 v0.1 共用同一 quorum；正式制度須拆分兩者並加入利益衝突迴避。

## 轉移與失竊爭議規則

1. 每個請求綁定帳本、政策雜湊、唯一識別與期限，不能跨帳本重播。
2. 支付先保留額度，等待結算期間可提出爭議；期間長度需後續業務驗證。
3. 爭議只能暫停相關額度，保留原紀錄，不直接宣判失竊。
4. 當事人可在裁決前提交一次異議，延長證據審查時間。
5. 嚴格多數簽署裁決：待結算支付可取消；已結算支付以反向分錄返還。
6. 餘額不足時不自動創造錢、不把短缺轉嫁第三方；保留案件與短缺資訊。
7. 真實外部資產是否能凍結或返還，取決於實際保管、合約及合作管道。
