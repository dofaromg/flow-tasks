## 一、固定輸出結構（product category full_result）

```
┌─────────────────────────────────────────┐
│  你的第一版產品方案                         │
│  以下內容可直接照順序往下做                  │
└─────────────────────────────────────────┘

【核心判斷】   ← 第一版真正要做什麼
【問題拆解】   ← 為什麼會卡住
【第一版範圍】 ← 包含什麼、不包含什麼
【執行順序】   ← Step 1 → Step 2 → Step 3
【先做 vs 先不做】← 排除項同等重要
【下一步建議】 ← 完成後往哪走

⚠ 常見失敗原因  ← warning
─────────────────────────────────────
這份方案可以直接作為你下一步實作、討論或交付的起點。
複製下來存到你的工具、傳給工程師、或直接開始第一步都可以。
```

## 二、每個區塊在解決什麼

| 區塊 | 解決的問題 |
|------|---------|
| 核心判斷 | 使用者不確定「到底該做什麼」—— 給一個清楚的結論 |
| 問題拆解 | 使用者知道自己卡了，但不知道卡在哪 —— 找出真正的阻塞點 |
| 第一版範圍 | 使用者不知道第一版該大還是小 —— 給明確的邊界 |
| 執行順序 | 使用者知道要做什麼，但不知道先做哪個 —— 給排序 |
| 先做 vs 先不做 | 使用者容易過度設計 —— 明確說出不做哪些 |
| 下一步建議 | 完成後不知道往哪走 —— 給延伸方向 |
| 警告 | 提醒常見的失敗模式 —— 降低犯錯率 |
| 方案 footer | 讓使用者知道這份內容可以拿去用 —— 強化交付感 |

## 三、為什麼這樣比較有成交感

### Before（舊輸出感受）
- 一串分析段落
- 感覺像 AI 在聊天
- 看完不知道下一步

### After（新交付感受）
- 有標頭（方案名稱）
- 有結構（核心判斷 → 範圍 → 順序 → 排除項）
- 有 footer（這份方案可以拿去用）
- 整體感覺像「拿到了一份文件」而不是「問了一個問題」

## 四、前端呈現要素

| 元素 | 位置 | 作用 |
|------|------|------|
| `product-result-header` | 結果區頂部 | 方案名稱 + 副說明 |
| `result-doc--product` | result-doc class | 讓區塊更像文件結構 |
| `result-block--accent` | 核心判斷區塊 | 金色左邊框 + 背景色 |
| `result-block--warn` | 先做 vs 先不做 | 視覺差異化 |
| `warning-block--product` | 警告區塊 | 左邊框 + ⚠ 標記 |
| `product-result-footer` | 結果區底部 | 交付物說明 + 使用提示 |
| `copy-btn--product` | 複製按鈕 | 金色樣式強化 |

## 五、當前 AI prompt 偏重（product v2）

```
summary  → 一句話說清楚「你現在真正該做的事」
breakdown → 三個讓第一版卡住的真正原因
directions → 兩個切法，每個說清楚包含什麼、不包含什麼
steps     → 先做 A → 再做 B → 再接 C（說明為什麼）
priorities → 包含「先不做的事」與原因
supplements → 上線前最小驗收清單 + 第一版成功的定義
warning   → 第一版最常失敗的原因
```
