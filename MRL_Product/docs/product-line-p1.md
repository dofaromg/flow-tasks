## 一、這條線在解什麼問題

**三種最常見的卡點：**

1. **順序問題**：想做網站 / 產品，但不知道先做頁面、功能還是金流，感覺每個都重要
2. **範圍問題**：一開始做就越做越大，不知道第一版要控制在哪裡
3. **收費入口問題**：有能力或有想法，但不知道怎麼讓陌生人付錢

**不是在解的問題（重要）：**
- 不是「幫你設計 UI」
- 不是「幫你寫程式碼」
- 不是「幫你做市場調查」

**是幫你做的事：**
- 把混亂的想法拆成有順序的計畫
- 讓你知道第一版要做什麼、不要做什麼
- 讓你拿到一份「可以動手的方案」

---

## 二、為什麼是 primary

| 理由 | 說明 |
|------|------|
| 需求普遍 | 幾乎所有想自己做東西的人都有這個問題 |
| 付費意願強 | 有明確可交付物（方案 / 計畫），容易判斷值不值 |
| 內容主線清晰 | 每個「做產品第 N 步卡在哪」都是一支短影片 |
| 與 MRL 故事對齊 | 這個系統本身就是這樣從想法走到上線的 |
| 容易展示 before/after | 「一堆想法」→「清楚計畫」視覺對比強 |

## 三、這條線如何從 category 變成產品線

### 第一層：category 入口
- `app.html?cat=product` → 進入 product 情境
- 預設選中，有 example prompts

### 第二層：專屬入口頁
- `/product.html` → 更詳細的情境說明 + 三個卡點
- 適合作為短影片 / 廣告的落地頁

### 第三層：AI 輸出偏重
- `ai.js` CATEGORY_ADDONS.product → 輸出偏向 MVP 切法 / 頁面順序 / 先不做什麼

### 第四層：子模板 quick modes
- 做第一版網站 / 做第一版產品 / 做收費入口 / 產品收斂
- 讓使用者更快找到自己的精確問題

### 第五層：pricing 情境
- 單次方案說明已聚焦到「產品 / 網站想法」
- 月費說明聚焦到「持續整理產品方向與功能優先順序」

## 四、首頁對齊設定

| 元素 | 設定 |
|------|------|
| h1 | 把你的產品想法丟進來，我幫你整理成第一版可執行方案 |
| sub | 含「產品 / 網站」明確字眼 |
| 主 CTA | 整理我的第一版方案 → `?cat=product` |
| usecase 卡 #1 | 做網站 / 做產品（主打 badge）|
| app 預設 | 無參數時預設 product |
| app loading | product 時顯示「整理第一版產品 / 網站方案」 |

## 五、導流重點

### 短影片最佳場景
- 「我想做網站但不知道從哪開始」→ 展示拆解結果
- 「第一版產品要包含什麼」→ 展示 MVP 清單輸出
- 「做收費網站的第一步」→ 展示付款流程拆解

### 社群貼文最佳場景
- 「你現在想做的第一版，應該比你想的小很多」
- 「做產品前，這件事比寫程式重要」

### 導流 URL
```
一般入口：    /app.html?cat=product
做第一版網站：/product.html（專屬頁）
特定場景：    /app.html?cat=product&prompt=...
```

## 六、當前 AI 輸出偏重（product 類別）

```
breakdown → 找到第一版範圍失控的原因
directions → 給出 MVP 切法建議
steps → 先做什麼頁面 → 再做什麼功能 → 再接什麼金流
priorities → 哪些「先不做」同樣重要
supplements → 上線前最小驗收清單建議
```
